# gfw404 Ultra Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build a secure, high-performance Hysteria-derived transport profile named `gfw404 Ultra` without inventing cryptography or adding DPI-evasion behavior.

**Architecture:** Keep wire compatibility with the upstream Hysteria 2 protocol. Add an opt-in application profile that composes standard TLS 1.3 verification, certificate pinning or a configured CA, QUIC path-MTU discovery, mature congestion control, and bounded resource settings. Keep performance measurement outside the protocol core so results can be reproduced without changing the wire format.

**Tech Stack:** Go 1.26, standard `crypto/tls` and `crypto/x509`, upstream `apernet/quic-go`, Cobra/Viper, Go unit tests and benchmarks, Linux `tc/netem` documentation for authorized lab testing.

**Spec:** This plan is the specification for the first `gfw404 Ultra` implementation.

## Global Constraints

- Do not add traffic camouflage, DPI evasion, protocol impersonation, port hopping, or mechanisms intended to bypass network controls.
- Do not invent cryptographic algorithms; use TLS 1.3 and the cryptographic primitives already provided by Go and QUIC.
- Preserve the upstream Hysteria 2 wire protocol and default interoperability when `profile` is unset.
- `ultra` mode MUST reject `tls.insecure: true` unless a certificate pin is configured; `tls.ca` is used with normal verification.
- `ultra` mode MUST leave path MTU discovery enabled unless the platform cannot support it.
- `ultra` mode MUST require credentials of at least 16 characters for password-based authentication.
- Security failures MUST fail closed with actionable configuration errors.

## Review Focus

- `ultra` plus `tls.insecure: true` without a pin must be rejected.
- A configured certificate pin must still verify the peer when normal CA verification is disabled.
- Invalid profile names and invalid QUIC bounds must be rejected before a socket is opened.
- Existing configs with no profile must retain their current parsing and wire behavior.
- UDP payloads larger than the QUIC datagram limit must continue to fragment safely without panics.
